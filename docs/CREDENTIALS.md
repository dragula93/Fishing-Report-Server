# Credentials and private inputs

Create your own values; the public examples contain placeholders only. Do not export n8n credentials into this repository, even encrypted ones.

| Item | Where you supply it | Purpose / handling |
|---|---|---|
| PostgreSQL admin password | `deploy/.env`: `POSTGRES_ADMIN_PASSWORD` | Generated by `scripts/init-env.py`; local database administration |
| n8n database password | `deploy/.env`: `N8N_DB_PASSWORD` | Generated; n8n's private database |
| Report database password | `deploy/.env`: `APP_DB_PASSWORD` | Generated; importer creates a private n8n Postgres credential |
| n8n encryption key | `deploy/.env`: `N8N_ENCRYPTION_KEY` | Generated; keep a protected backup with your database; changing it can make saved credentials unreadable |
| Runner broker token | `deploy/.env`: `N8N_RUNNERS_AUTH_TOKEN` | Generated shared secret for matching n8n/runners |
| n8n owner login | Initial editor setup | Your own email and password; not part of workflow configuration |
| SMTP/app password | n8n → Credentials → SMTP | Your provider's host, port, TLS and username; store the password/app key in the n8n credential UI |
| Optional Gmail app password | Same SMTP credential | Use your own Google account, enable two-step verification and create an app password where your account permits it; host `smtp.gmail.com`, port 465 with TLS, or the provider-supported alternative |
| Optional writer sign-in | `bash scripts/compose.sh exec -T writer codex login --device-auth` | Complete your own displayed authorization; stored only in private `codex_auth` volume; `codex login status` verifies it |
| WorldTides API key | `deploy/.env`: `WORLDTIDES_API_KEY` | Required for global tide predictions; create your account/key and verify credits/license for report redistribution |
| Optional commercial Open-Meteo key | `deploy/.env`: `OPEN_METEO_API_KEY` | Empty for eligible noncommercial free API use; set your key for customer endpoints |
| Subscribers, sender, operator and test inbox | `config/config.private.json` | Personal addresses; ignored by Git and read into the report database |
| GPX files | `data/gpx/*.gpx` | Your own waypoint correlation inputs; private, read-only helper mount; reference `/data/gpx/<file>.gpx` in each location's `ocean_features.gpx_inputs` |
| Official-warning adapter output | `data/alerts/<location_id>.json` | Location-scoped fresh output from your national authority integration; see LOCATIONS.md |

NOAA, the public MUR subset and local astronomy require no keys in this implementation. No n8n API token is needed by the provided installer. The writer implements the existing Codex/ChatGPT backend; an OpenAI API-key backend is not implemented and the `api_fallback_enabled` field must remain false. Reddit OAuth/direct scraping is not implemented; do not paste Reddit tokens into JSON.

SMTP binding is manual: assign your SMTP credential to **Send Archived Email Once** (Delivery) and **Send Operator Failure Notice Once** (Failure Handler). Test the credential, then enable those nodes on your instance. `email.smtp_ready` and execution mode form additional gates; enabling a node alone does not authorize production delivery.

Use [Google's app-password guidance](https://support.google.com/accounts/answer/185833), your SMTP provider documentation, [WorldTides API documentation](https://www.worldtides.info/apidocs), [Open-Meteo terms](https://open-meteo.com/en/terms) and [official Codex authentication guidance](https://developers.openai.com/codex/auth/) for account requirements. The pinned writer CLI supports device authorization; later CLI versions may have different options.

`deploy/.env` must be mode 600. Restrict the repository's private config and data to trusted host users while allowing the container's helper UID 10001 to read its mounts. Database backups, n8n volumes, writer sign-in, execution data, GPX snapshots and map attachments may contain secrets or personal/location data. Keep those backups outside the public repository. Revoking a key is required if a real key ever enters Git history; adding a later `.gitignore` entry does not remove earlier commits.
